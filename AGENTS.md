# Mojoverse

- Libraries live in `packages/`; executables and editor integrations live in `bins/`. Keep the landing README focused on dependency usage and links. Build and maintenance instructions belong in `docs/`.
- Package READMEs and API docs describe current usage, contracts, and requirements. Keep consumer-application details, implementation history, and local validation diaries in root maintenance docs or Git history, not package documentation. Preserve source attribution and license notices.
- Pixi is the build orchestrator. Internal dependencies use relative paths to this checkout; external consumers pin one Mojoverse Git revision and a package subdirectory. Do not add a second build graph.
- The root `pixi.toml` owns the compiler/MAX versions. All packages, including Raylib, use the same compiler lane: published nightly on `main`, stable on versioned `stable/<major>.<minor>` branches (currently `stable/1.2`). Use `scripts/toolchain.py update` to change pins and locks together; `check-workspace` rejects compiler/channel drift and detached internal dependencies.
- Load Modular's `mojo-syntax` skill before writing Mojo, plus its interop or GPU skill when applicable. Existing ExtraMojo APIs remain available; extraction into smaller packages does not authorize breaking them.
- Run `pixi run --locked test` and the `docs`, `graphics`, and `lsp` environments' `test-docs`, `test-graphics`, and `test-lsp` tasks on their supported hosts. CI tests the combined graph on every change, not only the edited package. See `docs/development.md` for scoped checks and platform requirements.
- Package changes need an installed-package check without source `-I` paths. Documentation examples run with the documented package's locked compiler, not whichever compiler the tools happen to find. Documentation conventions are in `docs/documentation.md`.
- Performance takes precedence over cosmetic refactors. Preserve native Clang `-O3 -march=native` and Mojo `-O3` host-targeted builds. Benchmark serially on an idle host, verify output before timing, and record raw samples and compiler flags. Native artifacts are host-specific, not portable release binaries.
- Retain per-package licenses and provenance. Keep private maintenance reports, credentials and machine-specific paths out of published files. The nightly updater only advances `main`; source compatibility repairs still require tests. Stable releases and backports are deliberate changes on versioned stable branches; do not rebase those branches onto nightly development.
